# การตรวจรับภาพและประสบการณ์ FB Staff APP

ตรวจต่อจาก fca0946 โดยใช้ Firebase Emulator และข้อมูลสังเคราะห์เท่านั้น เก็บภาพก่อนแก้ใน acceptance/before และหลังแก้ใน acceptance/final ทั้งภาพเต็มหน้าและภาพตามขนาดจอ ไม่มีการสร้าง mockup แทนหน้าจอจริง

## ข้อบกพร่องจากภาพจริงและการแก้ไข

## หลักการออกแบบที่ใช้

คงสีเขียวป่า งาช้างและทองจากรุ่นเดิม ลดภาพตกแต่งบนจอเล็กเพื่อให้ข้อความเด่น ใช้สถานะทั้งข้อความและสี ตัวเลขใช้ความกว้างสม่ำเสมอ ฟอนต์ไทยอยู่ในแพ็กเกจเดิม ไม่เพิ่มบริการภายนอกหรือ animation หนัก รองรับ reduced motion และ focus ของแป้นพิมพ์ใน dialog ด้วย native dialog และชื่อที่โปรแกรมอ่านหน้าจออ้างอิงได้

## จำนวนการกระทำในงานที่ทดลอง

นับหนึ่งการกรอกช่อง หนึ่งการกดปุ่ม และหนึ่งการเลือกไฟล์เป็นหนึ่งการกระทำ ไม่รวมการพิมพ์รายตัวอักษร การเลื่อนหน้าจอ หรือขั้นตอนภายในหน้าต่างเลือกไฟล์ของระบบปฏิบัติการ

- พนักงาน: กรอกรหัส + รหัสผ่าน + เข้าสู่ระบบ (3), เปิดงาน (1), เลือกรูป (1), กรอกบันทึก (1), ส่งงาน (1) = 7 การกระทำ ระบบกลับไปหน้าประวัติและแสดงรอตรวจอัตโนมัติ ไม่มีขั้นยืนยันซ้ำเพิ่ม ผู้ใช้ยังมีต้นทุนการเลื่อนแต่ส่วนบนสั้นลง
- ผู้จัดการอนุมัติ: เข้าสู่ระบบ (3), ดูรูป (1), ปิดรูป (1), อนุมัติ (1), ยืนยันอนุมัติ (1) = 7 การกระทำ เดิม 6 เพิ่มหนึ่งขั้นโดยตั้งใจเพื่อทวนงานและเจ้าของก่อนธุรกรรมคะแนน
- ผู้จัดการส่งกลับ: เข้าสู่ระบบ (3), ดูรูป (1), ปิดรูป (1), ให้แก้ไข (1), ระบุเหตุผล (1), ส่งกลับ (1) = 8 การกระทำ จำนวนเดิม แต่ป้ายปุ่มและบริบทชัดขึ้น
- ตรวจผลรายวัน: หลังตัดสินใจ ระบบโหลดผลและ KPI ใหม่อัตโนมัติ ไม่ต้องกดรีเฟรชผู้จัดการ ส่วนพนักงานอีกหน้าต่างใช้รีเฟรช 1 ครั้งเพื่อรับผลล่าสุด
- ทางเลือกที่ยังไม่ทำ: ปุ่มตัดสินใจในตัวดูรูปอาจลดการปิดรูปหนึ่งครั้ง แต่ต้องพิจารณา focus และการป้องกันการตรวจผิดงานเพิ่มเติม

## ขอบเขตและข้อจำกัด

ภาพหลักฐานทดสอบเป็น JPEG สีเดียวที่สร้างขึ้นเพื่อทดสอบเส้นทางอัปโหลด ไม่ใช่ภาพงานจริง การเลือกไฟล์ทำผ่าน browser automation ไม่ได้ทดสอบกล้องโทรศัพท์จริง ยังไม่ได้ตรวจ Safari/iOS, TalkBack/VoiceOver หรือรับรอง WCAG เต็มรูปแบบ ความชัดของวันที่ native date input ยังขึ้นกับภาษาของเบราว์เซอร์ หน้า checklist ยังยาวเมื่อเปิดหลายหมวด และประวัติ/รายงานที่มีข้อมูลมากต้องเลื่อนอ่าน

การอนุมัติใช้ API/transaction เดิมทั้งหมด การเปลี่ยนนี้เพิ่มเพียงการทวนก่อนเรียก API ไม่มีการแก้ Functions, schema, quota, points หรือ security rules ไม่ได้ใช้บริการ production

## หลักฐานจากการวัดตำแหน่งหลังแก้

ค่าจาก getBoundingClientRect ในเบราว์เซอร์ ขนาดจอ 393×851 เก็บในไฟล์ *-geometry.json: ปุ่มส่งงานแรกเริ่มที่ y=767 สูง 46 พิกเซล จึงอยู่ครบในจอแรก; รายการส่งตรวจผู้จัดการเริ่มที่ y=749; เมนูมือถือมีพื้นที่ 44×44 พิกเซล; ทางลัดหมวด checklist ย้ายจาก y≈848 ในรอบกลางมา y=250 ในรอบสุดท้าย ภาพก่อนแก้แสดงปุ่มส่งงานแรกอยู่ใต้ขอบจอ และรายการรอตรวจผู้จัดการยังไม่ปรากฏในจอแรก

การจัดการงาน/พนักงานเริ่มที่ y≈278 แทน y≈615 ในภาพก่อนแก้ โดยยังคงแท็บนำทางทั้งหมด ตัวเลขเป็นตำแหน่งของชุดข้อมูลทดสอบ ไม่ใช่ผลรับรองทุกความยาวชื่อหรือทุกจำนวนรายการ
