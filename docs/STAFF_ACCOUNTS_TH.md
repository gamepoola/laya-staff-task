# FB Staff APP — สมัครสมาชิกและจัดการบัญชีพนักงาน

## พนักงานสมัครครั้งแรก
1. ที่หน้าเข้าสู่ระบบ กด **สมัครพนักงานใหม่**
2. กรอกชื่อ–นามสกุล รหัสพนักงาน และรหัสผ่านพร้อมยืนยัน รหัสพนักงานใช้ a-z, 0-9, _ หรือ - ไม่เกิน 40 ตัว และไม่แยกตัวพิมพ์ใหญ่–เล็ก รหัสผ่านในหน้าสมัครกำหนด 12–128 ตัว
3. กด **สมัครสมาชิก** แล้วแจ้งผู้จัดการตรวจสอบตัวตนและเปิดสิทธิ์
4. หลังเปิดสิทธิ์ เข้าระบบด้วยรหัสพนักงานและรหัสผ่านที่ตั้งไว้

หากการเชื่อมต่อขาดระหว่างสมัคร ให้สมัครซ้ำด้วยรหัสและรหัสผ่านเดิม ระบบตรวจสอบความเป็นเจ้าของก่อนทำรายการต่อ ไม่เขียนทับบัญชีเดิม

## ผู้จัดการดูแลบัญชี
- ไปที่ **จัดการพนักงาน** รายชื่อแสดงรหัสพนักงานและสถานะ **รอเปิดสิทธิ์ / เปิดสิทธิ์แล้ว / ปิดสิทธิ์**
- เปิดสิทธิ์: เลือก **แก้ไข** ตรวจชื่อและรหัสกับพนักงานจริง ระบุแผนก จุดบริการ กะ แล้วเลือก **เปิดสิทธิ์ใช้งาน** และ **บันทึกพนักงาน**
- ระงับบัญชี: เอาเครื่องหมายเปิดสิทธิ์ออก แล้วบันทึก ระบบปฏิเสธการเข้าถึงข้อมูลและการทำรายการ โดยเก็บประวัติงานและคะแนนไว้
- ลืมรหัสผ่าน: เลือกแก้ไข กรอกรหัสผ่านใหม่อย่างน้อย 12 ตัว กด **ตั้งรหัสผ่านใหม่** และยืนยัน ส่งรหัสผ่านให้เจ้าของบัญชีเป็นการส่วนตัว ปุ่มบันทึกข้อมูลทั่วไปไม่เปลี่ยนรหัสผ่าน
- สร้างบัญชีให้พนักงานโดยตรงยังใช้ได้เหมือนเดิม

## ขอบเขตความปลอดภัย
- สมัครได้เฉพาะบทบาทพนักงานและเริ่มต้นปิดสิทธิ์เสมอ ไม่รับ role, points หรือ active จากผู้สมัคร
- ไม่เก็บรหัสผ่านใน Firestore, audit log หรือไฟล์สาธารณะ ให้ Firebase Authentication จัดเก็บ
- การสมัครซ้ำไม่แก้ไขโปรไฟล์เดิมหรือเพิ่มสิทธิ์
- เฉพาะผู้จัดการที่เปิดสิทธิ์อยู่เท่านั้นที่ตั้งรหัสผ่านพนักงานได้ ไม่รองรับการตั้งรหัสผ่านผู้จัดการจากหน้านี้
- คง Firestore Rules, Storage Rules, โควตา, คะแนน, การอนุมัติ, ภาพหลักฐาน, การล้างรูปเจ็ดวัน และ offline drafts เดิม
- ไม่เปิดให้เปลี่ยนรหัสพนักงานหรือลบบัญชีถาวรผ่านหน้านี้ เพื่อรักษาการอ้างอิงและประวัติ
- การรีเซ็ตรหัสผ่านเพิกถอน refresh token แต่ ID token ที่ออกไปแล้วอาจยังใช้ได้จนหมดอายุ หากต้องระงับการเข้าถึงทันที ให้ปิดสิทธิ์พนักงานด้วย

## ก่อนเปิดใช้งานจริง
รอบนี้ทำงานและทดสอบเฉพาะ Firebase Emulator ไม่ได้ deploy หรือแก้ไข production ต้องนำ Functions และหน้าเว็บรุ่นนี้ขึ้นสภาพแวดล้อมที่ได้รับอนุมัติพร้อมกันก่อนใช้จริง ตรวจ Email/Password provider, password policy และ App Check ของ Authentication/Functions บนโครงการจริงก่อนเปิดสมัครสาธารณะ ผู้จัดการต้องตรวจสอบตัวตนก่อนเปิดสิทธิ์เสมอ บัญชี Auth ที่สมัครไม่จบอาจยังค้างอยู่โดยไม่มีสิทธิ์เข้าถึงข้อมูลและสามารถสมัครซ้ำเพื่อดำเนินการต่อได้
